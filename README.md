# Кулинарный новостной портал

**1. Описание предметной области**
*Предметная область:* Кулинарный новостной портал.
*Бизнес-цель приложения:* Увеличить вовлеченность и удержание пользователей путем предоставления кулинарного контента и оперативного информирования аудитории о новых тематических подборках рецептов.

**2. Проектирование функционала приложения**
*Функционал:*
* Регистрация, авторизация и аутентификация пользователей.
* Создание, чтение, редактирование и удаление кулинарных рецептов и новостных статей.
* Добавление рецептов в список "Избранное".
* Получение рекомендаций на основе истории сохраненных рецептов пользователя (через gRPC-сервис).
* Рассылка и получение push-уведомлений в реальном времени при публикации новых тематических подборок (через RabbitMQ и WebSocket).

*Роли пользователей:*
1. **Читатель (User):** может просматривать рецепты, добавлять их в избранное, получать рекомендации и уведомления.
2. **Администратор (Admin):** имеет полный доступ к CRUD-операциям над рецептами, тегами и рассылкам.

**3. Сценарии использования**
* *Сценарий 1: Чтение и сохранение рецепта (Читатель).* Пользователь авторизуется в системе, открывает главную страницу, переходит в каталог рецептов, открывает карточку рецепта и нажимает кнопку "Добавить в избранное".
* *Сценарий 2: Создание статьи (Администратор).* Администратор переходит в панель управления, отправляет POST-запрос с данными нового рецепта (название, текст, ингредиенты, теги). Система сохраняет данные в БД.
* *Сценарий 3: Рекомендация контента (Система/Читатель).* При переходе читателя в личный кабинет, API Service запрашивает у gRPC-сервиса список ID рекомендованных рецептов на основе сохраненных ранее статей пользователя. Читатель видит блок "Вам может понравиться".
* *Сценарий 4: Уведомление о выходе подборки (Система/Читатель).* Администратор публикует новую кулинарную подборку. API Service отправляет событие в RabbitMQ. Сервис уведомлений (Notification Service) забирает событие и через WebSocket рассылает уведомление всем читателям, находящимся онлайн.

**4. Архитектура приложения**
* **Слой данных:** PostgreSQL (реляционная БД), SQLAlchemy (ORM для взаимодействия с БД), Pydantic (сериализация и валидация).
* **Основной сервер (API Service):** FastAPI. Обрабатывает REST API запросы клиентов (CRUD операции), взаимодействует с БД и другими сервисами.
* **Внутренний сервис (gRPC Service):** Выполняет вычислительную задачу по подбору рекомендаций. Взаимодействует с API Service по RPC (Protocol Buffers).
* **Асинхронные уведомления:** RabbitMQ выступает брокером сообщений для передачи событий от API Service. Notification Service (Socket Service) принимает эти сообщения и доставляет их клиентам по WebSocket.
* **Развертывание:** Docker и Docker Compose для контейнеризации всех узлов.
