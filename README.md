## Введение
**Предметная область:** Кулинарный новостной портал.
Проект представляет собой распределённую информационную систему, обеспечивающую публикацию кулинарного контента, персонализированный подбор рекомендаций и оперативное информирование пользователей.

## Сценарии использования приложения
**Бизнес-цель:** Увеличить вовлеченность и удержание пользователей за счет персонализации кулинарного контента и оперативного информирования аудитории о новых тематических подборках рецептов.

**Функциональность приложения:**
Для достижения бизнес-цели приложение реализует следующий функционал:
* Регистрация, авторизация и аутентификация пользователей (JWT-аутентификация).
* Создание, чтение, редактирование и удаление кулинарных рецептов и новостных статей.
* Добавление рецептов в список "Избранное".
* Получение персональных рекомендаций на основе истории сохраненных рецептов пользователя (через gRPC-сервис).
* Рассылка и получение push-уведомлений в реальном времени при публикации новых тематических подборок.

**Роли пользователей:**
1. **Читатель (User):** имеет право просматривать рецепты, добавлять их в избранное, получать рекомендации и уведомления.
2. **Администратор (Admin):** имеет полный доступ к созданию, просмотру, редактированию и удалению рецептов и тегов, а также управляет рассылками.

**Конкретные сценарии использования:**
1. *Сценарий 1: Чтение и сохранение рецепта (Читатель).* Пользователь авторизуется в системе, открывает главную страницу, переходит в каталог рецептов, открывает карточку рецепта и нажимает кнопку "Добавить в избранное".
2. *Сценарий 2: Создание статьи (Администратор).* Администратор переходит в панель управления, отправляет POST-запрос с данными нового рецепта (название, текст, ингредиенты, теги). Система сохраняет данные в БД.
3. *Сценарий 3: Рекомендация контента (Система/Читатель).* При переходе читателя в личный кабинет, API Service запрашивает у gRPC-сервиса список ID рекомендованных рецептов на основе сохраненных ранее статей пользователя. Читатель видит блок "Вам может понравиться".
4. *Сценарий 4: Уведомление о выходе подборки (Система/Читатель).* Администратор публикует новую кулинарную подборку. API Service отправляет событие в RabbitMQ. Сервис уведомлений (Notification Service) забирает событие и через WebSocket рассылает уведомление всем читателям, находящимся в онлайне.

## Архитектура приложения
Архитектурные решения основаны на микросервисном подходе и использовании современных сетевых протоколов. 

**Стек технологий и обоснование их использования:**
* **PostgreSQL:** Реляционная БД, обеспечивающая строгую целостность данных и поддержку сложных связей между сущностями.
* **SQLAlchemy & Pydantic:** ORM-библиотека для безопасного взаимодействия с БД на уровне объектов Python и инструмент для строгой валидации входящих данных.
* **FastAPI (API Service):** Высокопроизводительный асинхронный веб-фреймворк, идеально подходящий для маршрутизации REST API запросов.
* **gRPC (gRPC Service):** Выполняет вычислительную задачу по подбору рекомендаций. Взаимодействует с API Service по RPC (Protocol Buffers), так как этот протокол обеспечивает быстрый межсервисный обмен данными.
* **RabbitMQ:** Надежный асинхронный брокер сообщений. Обеспечивает отказоустойчивую передачу событий от основного API к сервису уведомлений, снимая нагрузку с основного потока.
* **WebSocket (Socket Service):** Технология двунаправленного обмена, необходимая для мгновенной доставки push-уведомлений подключенным клиентам.
* **Docker & Docker Compose:** Применяются для изоляции, контейнеризации всех узлов распределенной системы и обеспечения идентичности среды разработки и продакшена.

## Структура базы данных
Для реализации функционала спроектированы 3 основные сущности (`User`, `Recipe`, `Tag`) и 2 связи типа "многие-ко-многим", обеспечивающие чтение, запись и редактирование данных в соответствии с требованиями предметной области. 

**Логическая схема:**
*   Сущность **User (Пользователь)** хранит учетные данные. Связана с рецептами через промежуточную таблицу `user_favorites` (Многие-ко-многим).
*   Сущность **Recipe (Рецепт)** хранит контент. Связана с тегами через промежуточную таблицу `recipe_tags` (Многие-ко-многим).
*   Сущность **Tag (Тег)** используется для категоризации и поиска кулинарных статей.
